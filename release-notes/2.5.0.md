## 2.5.0

This release is a maintenance and feature update for the fork, based on the last upstream 2.4.4 release.

### Added

- Choose the output format (PNG, transparent PNG, JPG, WEBP or PDF) directly in the export preview. ([#92](https://github.com/zhouhua/obsidian-export-image/issues/92))
- Customize the author area: avatar size, author name font size and author area top padding. The settings are available in both the settings tab and the export preview, and existing vaults receive defaults through a nested settings merge.
- Optional body font size override. Leave the field empty to keep the current theme font size.
- Add a fallback callout icon when the cloned content has no icon or only an empty icon element. ([#117](https://github.com/zhouhua/obsidian-export-image/issues/117), approach from [#120](https://github.com/zhouhua/obsidian-export-image/pull/120))
- Wait for async code block processors (Dataview, SQLSeal, etc.) to settle when exporting rendered Markdown. ([#127](https://github.com/zhouhua/obsidian-export-image/issues/127), approach from [#129](https://github.com/zhouhua/obsidian-export-image/pull/129))
- Load the Finnish and Italian locales that were already present in the repository.

### Fixed

- Exporting another file from the file menu or exporting a selection could use the active editor content instead of the requested content. This was a regression from the live-preview export change.
- Reading-mode exports produced an empty image because there is no `.cm-content` element in reading mode. ([#4](https://github.com/zhouhua/obsidian-export-image/issues/4))
- Quick selection export could copy an empty image because the preview mounted before the content was loaded.
- The Copy button could be disabled for every format when the clipboard capability probe failed. The probe no longer writes to the clipboard. ([#56](https://github.com/zhouhua/obsidian-export-image/issues/56))
- A failed image request could pass an empty response to `FileReader.readAsDataURL`, throwing a `TypeError` and leaving the export hanging. ([#41](https://github.com/zhouhua/obsidian-export-image/issues/41))
- Single-page PDF export requested `image/pdf` from the canvas, then handed the resulting data to jsPDF as JPEG. ([#69](https://github.com/zhouhua/obsidian-export-image/issues/69), [#83](https://github.com/zhouhua/obsidian-export-image/issues/83))
- Folder exports captured the detached markdown container instead of the styled export root, so theme styles, custom CSS snippets, title, padding, watermark and author info were missing. ([#125](https://github.com/zhouhua/obsidian-export-image/issues/125))
- Embedded notes kept their scrollbars in exported images. ([#65](https://github.com/zhouhua/obsidian-export-image/issues/65))
- Long code blocks could be clipped at the bottom by a theme `max-height`. ([#95](https://github.com/zhouhua/obsidian-export-image/issues/95))
- Checked task list items were exported as unchecked. ([#49](https://github.com/zhouhua/obsidian-export-image/issues/49))
- Callout icons could disappear from exported images. ([#117](https://github.com/zhouhua/obsidian-export-image/issues/117))
- Rendered Markdown exports could capture async code blocks before they finished loading. ([#127](https://github.com/zhouhua/obsidian-export-image/issues/127))
- `split mode = none` still split folder exports at the configured split height.
- Empty notes could produce no pages and fail the PDF path.
- Split changes were reported while React was rendering, and the preview height observer missed the moment when the target mounted.
- The editor `printing` state was not restored if reading or cloning the editor DOM failed.
- A UI-only `--line-height-tight` override leaked into exported content. ([#80](https://github.com/zhouhua/obsidian-export-image/issues/80))
- Format availability now verifies the actual encoded MIME type instead of accepting a PNG fallback as support for every format.

### Changed

- Updated jsPDF to 4.2.1, lodash to 4.18.1, jszip to 3.10.2, esbuild to 0.25.12 and React to 19.3.1.
- Removed the unused `dom-to-image-more` package; the plugin uses the vendored `src/dom-to-image-more.js`.
- Moved the Node and React type packages to `devDependencies` and pinned the Obsidian types to `^1.14.4`.
- Aligned the XO configuration with the existing code style and made `npm run lint` pass.
- Added a release workflow that audits production dependencies, lints, builds, packages a versioned zip and uploads the release assets.
- `npm audit --omit=dev` is clean after the dependency updates.

### Known issues

- Cross-origin iframe and web embeds are still not captured. ([#85](https://github.com/zhouhua/obsidian-export-image/issues/85), [#90](https://github.com/zhouhua/obsidian-export-image/issues/90))
- Theme background images may still be missing from exports. ([#101](https://github.com/zhouhua/obsidian-export-image/issues/101))
- There is no option yet to hide image captions. ([#119](https://github.com/zhouhua/obsidian-export-image/issues/119))
- Folder export still saves each note separately, so desktop users can see multiple save dialogs. ([#125](https://github.com/zhouhua/obsidian-export-image/issues/125))
- The iOS-specific failure with checked task lists was not reproduced; this release only preserves the checked state. ([#49](https://github.com/zhouhua/obsidian-export-image/issues/49))
- `local()` font faces are still not embedded. ([#79](https://github.com/zhouhua/obsidian-export-image/issues/79))
